# Вход по почте и Яндекс ID

## Настройка владельцем
Откройте `/admin/#auth` — «Вход и письма». Другие роли не меняют способы входа.

### Одноразовый код
1. Создайте аккаунт [Resend](https://resend.com/), подтвердите свой домен отправителя.
2. Создайте API-ключ отправки и впишите его в защищённое поле. Укажите email с подтверждённого домена.
3. Включите коды на почту, сохраните, нажмите «Отправить тестовое письмо владельцу».
4. В `/login.html` пользователь вводит любой email, включая `@yandex.ru`, получает код и подтверждает вход.

Без ключа и подтверждённого отправителя сервер возвращает явную ошибку. Ответ об отправке появляется только после подтверждения приёма письма почтовым API; это не гарантия доставки во «Входящие». Проверьте также папку «Спам». Обычный пароль Яндекс Почты не используется.

Код состоит из 6 цифр, действует 10 минут, используется один раз и привязан к браузеру запроса. До 5 попыток проверки; не чаще 1 письма в минуту, 5 писем в час на адрес и 20 на IP. Коды хранятся в виде HMAC, IP — в виде необратимого серверного идентификатора. Код не возвращается в JSON и не выводится в журнал.

### Кнопка Яндекс ID
1. Создайте [OAuth-приложение Яндекса](https://oauth.yandex.ru/client/new) для веб-сайта.
2. Redirect URI: `https://video-maker-every-thing.izhanshahfarul.chatgpt.site/api/auth/yandex/callback`.
3. Разрешения: `login:email`, `login:info`.
4. Введите Client ID/Client Secret в админке, включите способ и сохраните.

Используются state с привязкой к браузеру, PKCE S256, серверный обмен кода и одноразовое потребление состояния. OAuth-токен не возвращается браузеру. Если email уже существует, автоматического объединения нет: войдите по коду и подключите Яндекс в кабинете → «Безопасность». Это сохраняет подписку существующего аккаунта и не даёт завладеть им одним совпадением email.

### Сеансы и данные
HttpOnly/Secure/SameSite=Lax cookie с префиксом __Host-, срок 7 дней. В базе — только хеш случайного токена. Вход по подтверждённой почте сохраняет существующий ID пользователя и подписку; новые пользователи получают Free. Роли и блокировка проверяются на сервере, в том числе перед выдачей HTML админки. Выход отзывает текущий локальный сеанс; затем выполняется выход из ChatGPT. Источники и локальная библиотека не переносятся между разными аккаунтами автоматически.

Ключи почты и OAuth шифруются AES-GCM с существующим AI_CONFIG_KEY хостинга. Пустое поле сохраняет секрет, отдельная галочка удаляет. Миграции 0004/0005 добавляют конфигурацию, одноразовые коды, сеансы, OAuth-состояния/идентичности и лимиты. Продакшен не содержит тестовых отправителей/ключей.

## Кнопки «ИИ и скиллы»
Раньше формы открывались ниже видимой части страницы. Теперь открытая форма прокручивается в экран, получает фокус; ошибки видны внутри формы, успешный ответ — в уведомлении. Сохранение, импорт скилла и обнаружение модели проверены браузером на отдельной тестовой базе.

## Наблюдаемый результат
В этой поставке реализованы маршруты и интерфейс входа, но реальные почтовые/OAuth-ключи ещё не заданы пользователем. Сквозной браузерный тест и серверные тесты используют отдельные фикстуры с имитацией внешнего почтового API, не отправку настоящих писем. После настройки отправителя владельцу доступна настоящая кнопка проверки доставки.
