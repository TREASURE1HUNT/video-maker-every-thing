# Cover uploads and AI reliability

- Cover background can be a timeline frame or a user-uploaded PNG/JPEG/WebP up to20MB/64MP. The file is decoded and optimized to2048px WebP, with a bounded complete data URI stored in the project. It persists on reload and JSON export/import. No upload to the language model occurs; chat receives only cover text/style and a boolean that a custom image exists. Switching back to a frame or removing the uploaded background is explicit. Titles can be empty for an image-only cover. Frame time is rounded to hundredths.
- OpenRouter montage calls request JSON mode with reasoning disabled when supported, rather than relying on a prose-only instruction. One bounded retry repairs malformed JSON/invalid plans; an unsupported-format400 retries once without that optional format parameter. Managed Gemma endpoint limits/unavailability can retry through OpenRouter Auto, clearly labeled in the response. A single reservation covers both attempts. Unknown assets and materially out-of-range timings remain rejected; numeric time strings and <=0.05s source-end rounding normalize safely.
- Provider authentication, balance, model, rate-limit, timeout and invalid-output failures get distinct public messages. Failed reservations still refund once. Logs include only request ID/model/status/code, never raw provider content, API secrets, prompts or materials.
- Existing provider model IDs, enabled states and pricing remain unchanged. No paid model is enabled automatically. Runtime secrets remain in the existing Sites environment.
- Primary technical references consulted: https://openrouter.ai/docs/guides/features/structured-outputs and public https://openrouter.ai/api/v1/models. Current catalog lists the configured Gemma4 free ID and response_format/reasoning parameters.
- Tests and real production check are recorded in outputs/cover-ai-evidence/VERIFICATION.txt. Local UI test uses a clearly isolated mock provider, not real inference; production admin test uses the existing server key without exposing it.
